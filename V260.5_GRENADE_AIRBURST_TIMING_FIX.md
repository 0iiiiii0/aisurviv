# V260.5 Grenade Airburst + Anti-Timing Fix

This patch implements two linked grenade-AI changes on top of V260.4.

## 1. Physics-based airburst timing

- Removed the remaining fixed Frag/MIRV cook values (`430 ms` / `360 ms`) from active grenade paths.
- Removed the active planner's old `3.35 s` / `3.45 s` flight targets.
- `solveForbiddenGrenadeThrow()` now searches the useful moving-impact window (`0.68 s` to `1.68 s`) and prefers the **longest feasible flight** that still:
  - reaches the requested target within 1.5 units,
  - retains at least 4.25 units/s horizontal speed,
  - avoids blocked/unsafe landing points,
  - avoids near-wall bounce-back risk.
- Cook time is derived from the actual 4.0 s fuse:
  - `cook = 4.0 - flight - detonationBias`
  - default detonation bias = `55 ms`.
- The solver now includes the real `WeaponManager.throwThrowable()` launch origin: the rotated throwing-hand offset `(0.5, -1.0)`, instead of incorrectly spawning the simulation from player center.
- The solver compensates the game's inherited thrower velocity (`player moveVel * 0.6`).
- Added `solveForbiddenPrimedGrenadeRelease()` for grenades whose pin is already pulled. It solves aim/mouse strength from the **immutable remaining fuse** instead of pretending the grenade can be cancelled or recooked.

Typical stationary Frag results after the change:

| Target distance | Flight | Cook | Residual fuse at target |
| --- | ---: | ---: | ---: |
| 14.5 | ~1.255 s | ~2.690 s | ~55 ms |
| 20 | ~1.405 s | ~2.540 s | ~55 ms |
| 25 | ~1.505 s | ~2.440 s | ~55 ms |
| 28 | ~1.555 s | ~2.390 s | ~55 ms |
| 30 | ~1.58 s | ~2.365 s | ~55 ms |

This intentionally reduces the old high-speed/short-flight behavior that could force the bot to hold a live grenade for more than three seconds.

## 2. Anti-timing behavior after/before pin pull

- Before the pin is pulled, a close visible/rushing enemy can cancel the grenade commit legally and return the bot to its previous weapon.
- After this pre-pin interruption, Frag/MIRV commits are suppressed for 850 ms to avoid equip/cancel spam from jiggle peeks.
- Once the pin is pulled, the AI **never cancels the grenade**.
- While holding a live Frag/MIRV, the bot re-solves the trajectory about every 55 ms using:
  - current authoritative bot velocity where available,
  - current tracked enemy position,
  - enemy velocity with long-horizon damping,
  - current remaining fuse.
- If the tracked enemy becomes visible at close range, rushes the bot, or the bot was just damaged, the AI shortens the hold to the earliest legal server release (`>100 ms` cook floor) and throws the live grenade instead of continuing to cook while exposed.
- If an exact airburst is no longer physically possible during an emergency, the bot performs a hard disposal/pressure throw rather than attempting an impossible cancel.
- Existing `holdMovementDir` behavior is retained so movement stays stable during the final throw window; the current authoritative move velocity is fed back into the solver.

## Other correctness fix

`evaluateForbiddenGrenadeOpportunity()` now receives the true grenade arrival cost (`cookMs + flight time`) instead of flight time alone when evaluating whether a healing punish can arrive in time.
