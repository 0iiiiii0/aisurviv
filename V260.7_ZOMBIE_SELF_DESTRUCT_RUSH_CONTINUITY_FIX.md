# V260.7 — Zombie Self-Destruct Rush Continuity Fix

## Reproduced root cause
V260.6 cancelled `zombieRushing` immediately whenever the 150 ms LOS/path sample returned false once. A tree edge, door frame, building corner, water sample, or lateral target movement could therefore turn an already-started charge off. The fallback zombie movement is straight-line only, so the bomber could then press into an obstacle and appear to stop.

An A/B regression reproduces the old behavior exactly:
- clear lane: `zombieRushing = true`
- one forced LOS false sample: old V260.6 immediately changes to `false`

## Fixes
1. Rush is now committed after a clear close-range lane starts it. A transient LOS loss no longer cancels the rush. It only disengages if the target escapes beyond 1.5x the trigger range.
2. Added short-range tangent probing while a committed bomber is blocked, so it keeps moving around common tree/door/corner blockers instead of simply pushing straight into them.
3. Rush movement speed is now an authoritative `1.5x` multiplier in `Player.recalculateSpeed()`. Windwalk remains only as the networked FX/sound marker and is no longer the source of rush movement speed.
4. Self-destruct contact detonation is no longer gated by the ordinary 900 ms melee cooldown. A bomber with clear LOS detonates immediately on contact.
5. The existing safety rule is preserved: a bomber still cannot detonate through a wall/obstacle; contact explosion still requires clear LOS.

## Regression coverage
`zombieSelfDestructRushContinuitySmokeTest.ts` verifies:
- normal zombie speed -> committed rush speed is exactly 1.5x;
- one LOS failure after rush start does not clear `zombieRushing`;
- blocked committed rush still emits movement;
- an active melee cooldown cannot stall clear contact detonation.

Existing zombie LOS and zombie mode tests also remain green.
