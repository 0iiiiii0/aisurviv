# V31 靶场 UI 与有利掩体保护

## 靶场 UI 根因

玩家加入凭据过去会在移动标靶子进程尚未连接时立即返回。玩家先进入房间后会收到 `started=false`：

- Arena 锁定仍然生效；
- 顶部持续显示 `Waiting for players...`；
- 初始本地状态没有完整进入正常对局流程；
- 武器、护甲和物品栏中的空 `<img>` 会显示为浏览器损坏图片图标；
- 训练统计容器因为与全宽等待提示共用父容器，被撑成整屏宽度。

## 靶场修复

1. 创建训练房后，服务器先启动移动标靶。
2. API 轮询房间状态，确认至少一名服务器 AI 已连接。
3. 只有确认标靶就绪后，才向玩家返回加入凭据。
4. 标靶 9 秒内没有启动时，关闭异常房间并返回明确错误。
5. 客户端在训练地图载入及收到训练统计包时，均主动关闭旧等待提示。
6. 训练 HUD 使用固定宽度、独立定位，不再继承全宽等待提示的布局。
7. 训练模式初始化期间隐藏空图片的损坏图标；真实资源 URL 写入后自动恢复显示。

## 有利掩体保护

新增 `server/src/bot/coverPreservation.ts`，判断阻挡物由哪一侧占有。

当可破坏掩体满足以下条件时，AI 不再攻击：

- 掩体位于 AI 与敌人之间；
- AI 位于掩体近侧，并且靠近掩体边缘；
- 敌人明显位于掩体远侧；或
- 该障碍物正是 Pro AI 当前选中的战斗掩体。

此时 AI 会保留屏障，通过侧移、探头、绕侧或等待敌人暴露继续战斗。

仍允许攻击：

- 明显位于敌人近侧的掩体；
- AI 距离很远、并未实际获得保护的障碍物；
- 必须清除的资源入口障碍；
- 不会伤害 AI/队友且具有明确收益的敌侧爆炸物。

该规则同时应用到普通/Pro 战术破掩体、1v1 破坏逻辑和 Forbidden 权威弹道决策。
