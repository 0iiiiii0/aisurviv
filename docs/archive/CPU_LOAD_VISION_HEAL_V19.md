# V19：CPU负载控制、视野与战斗修复

## 1. 修复AI瞄准但不开枪

旧逻辑在满足反应时间、射程、弹药和弹道条件后，仍会按 `shootConfidence` 做一次随机判定。某些帧中瞄准已经对齐，但随机判定失败，随后又被其他动作状态覆盖，表现为AI持续盯着玩家却不射击。

V19将开火改为硬条件判定：

- 已完成反应延迟；
- 当前武器有弹药；
- 目标在有效射程内；
- 当前弹道没有被墙体、门、烟雾或其他实心障碍物阻挡；
- 准星已进入武器要求的误差范围。

满足以上条件后会稳定发送射击输入。难度差异仍由反应速度、瞄准误差、提前量、转向速度、射击节奏和移动策略体现，不再通过“随机不开枪”体现。

## 2. CPU负载控制

默认阈值：

- 软阈值：70%；
- 目标上限：80%。

服务端和AI进程每秒读取Windows整机CPU时间差。达到软阈值后：

- 自动增加AI补入间隔；
- 降低AI决策频率；
- 降低空间索引和玩家记忆刷新频率。

达到80%后：

- 暂停生成和连接新的AI；
- 已存在AI进入更强的节流状态；
- CPU下降后自动恢复补人。

可通过环境变量调整：

```powershell
$env:SURVIV_CPU_SOFT_LIMIT = "70"
$env:SURVIV_CPU_HARD_LIMIT = "80"
```

这是应用层自适应目标，不是Windows内核级硬配额。其他程序持续占用CPU、驱动中断或瞬时尖峰仍可能让整机读数短暂超过80%。

## 3. 降低大量AI和生成阶段的开销

- 普通模式和50v50的单个AI工作进程最多承载8个AI。
- 每个AI仍按后台配置的时间间隔依次连接，不会8个同时加入。
- 开发模式使用 `ts-node/register/transpile-only`，避免每个机器人工作进程重复执行完整TypeScript类型检查。
- Windows下将AI工作进程优先级设为低于正常。
- 同一工作进程中的AI思考帧错开，避免同一毫秒集中执行路径搜索。
- AI数量增加时，空间网格、玩家记忆和非战斗决策自动降频。
- 战斗逻辑保留较高刷新频率，非战斗搜刮和探索优先降频。

## 4. 远距离视野约束

远距离开火必须同时满足：

- 目标位于AI当前实际装备并启用的倍镜画面内；
- 目标是当前客户端最近收到的可见对象，而不是背包中最高倍镜推算出的范围；
- 远距离目标数据足够新；
- 目标与AI之间有真实视线和弹道。

目标离开画面或只剩旧坐标后，AI不能继续根据历史位置远距离开枪。近距离仍允许较短时间的目标连续性，避免玩家经过门框时AI立即完全失忆。

## 5. 打药时移动

AI开始治疗后不再原地等待：

- 有硬掩体时，继续向掩体更深处移动；
- 已经完全遮挡时，沿掩体侧向移动并略微远离最后威胁方向；
- 没有明确敌人时，在附近做短距离、带避障的移动，而不是静止；
- 敌人重新获得视线、靠近、造成伤害，或毒圈/空袭变得危险时，立即取消治疗并转为撤退或反击。

## 6. 兼容性

V19基于V18完整项目制作。网络协议版本不变，客户端无需新增协议字段，但客户端和服务端仍建议使用同一完整版本。
