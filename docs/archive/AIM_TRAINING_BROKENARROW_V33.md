## 靶场无法加载

共有 6 个 `aim_training` 记录会话。其中一个会话只出现标靶自身，没有人类玩家，持续 **935 秒**，期间标靶触发了 **760 次**卡路恢复且位置没有变化。

### 根因

旧创建顺序是：

1. 创建房间；
2. 先启动标靶进程；
3. 等待标靶连接；
4. 再把人类玩家的进入令牌返回给浏览器。

这使标靶可能长期独占房间。客户端又在地图加载时提前隐藏等待状态并显示训练统计框，因此画面看似进入靶场，实际上房间仍未完成“人类＋标靶”的初始化。

### V33 修复

- 立即返回人类玩家令牌；
- 服务器确认人类进入后，才启动移动标靶；
- 第一份训练统计只在标靶实际存在后发送；
- 客户端在收到该权威统计包前保持“正在连接移动标靶…”；
- 标靶逻辑在普通卡路与战术逻辑之前执行，不再进入 `regroup` 或资源状态机。

## V31 空袭记录问题

| 指标 | 结果 |
|---|---:|
| 空袭警告 | 50 |
| 撤离开始 | 45 |
| 撤离结束 | 45 |
| 撤离持续时间中位数 | 102 ms |
| 最短撤离 | 23 ms |
| 最长撤离 | 1766 ms |
| 被标为最高优先级的警告 | 0 |
| 警告后 6 秒内受伤 | 42 / 50 |
| 警告首次落弹倒计时中位数 | 269 ms |

45 次撤离的中位持续时间只有 102 ms。其原因不是 AI 跑得足够快，而是警告链在“信标投射物消失、飞机或炸弹警告尚未出现”的阶段短暂变空，AI 立即结束撤离，随后下一条警告又重新启动。

记录器中 `possibleAirstrikeDamage` 始终为空，因此 V31 无法可靠把每次死亡归因到具体空袭。V33 已保留更完整的危险区上下文，下一批日志可直接复核。

## Broken Arrow 执行问题

V31 记录到 35 次信标释放。快速连续释放中，低于 1 秒的间隔中位数仍为 **628 ms**，主要被普通投掷动画和旧飞机间隔限制。

旧版还只有 5 条横向覆盖线，容易留下侧边缺口；小库存时又保留过多信标，首轮不能形成完整覆盖。

### V33 修复

- 横向覆盖线：`5 → 7`；
- Broken Arrow 飞机间隔：`800 ms → 380 ms`；
- Broken Arrow 信标投掷动画：`约普通投掷时长 → 0.11 s`；
- 小库存时允许首轮使用全部信标，大库存只保留 1 枚；
- 警告半径：`34`；
- 高杀伤核心半径：`25`；
- 覆盖评分放宽，避免第一枚大范围信标导致后续覆盖点被错误否决。

## 空袭躲避增强

- 空袭危险区不再每帧整体替换，而是跨阶段合并并保留；
- 信标、飞机和炸弹之间的短暂数据间隙不会被判定为安全；
- 逃生点同时计算所有重叠空袭，而不是只躲当前选中的一个；
- 高杀伤核心和即将落弹区域使用更大的安全距离；
- 逃生目标锁定更久，避免 20–100 ms 的状态抖动；
- 撤离时自动切换近战，避免持枪移动减速；
- 若 AI 已拉开投掷物保险且空袭即将落下，会立即安全释放，下一帧直接逃生，而不是继续长时间烹雷。
