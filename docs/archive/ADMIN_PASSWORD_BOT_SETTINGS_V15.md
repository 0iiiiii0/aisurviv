# V15：后台密码与人机补入设置

## 后台登录

后台页面 `/admin/` 现在只显示密码登录界面。未建立有效管理会话时，所有 `/admin-api/*` 管理接口都会返回 `401 Unauthorized`。

密码处理：

- 首次启动时，如果没有 `survivio-admin-auth.json`：
  - 优先使用环境变量 `SURVIV_ADMIN_PASSWORD`；
  - 未设置环境变量时，服务端生成随机初始密码，并在控制台中仅显示一次。
- 密码通过带随机盐的 `scrypt` 保存，密码文件中没有明文。
- 登录成功后创建随机会话令牌，默认有效期 12 小时；令牌只保存在当前浏览器标签页的 `sessionStorage`。
- 后台可以修改密码。修改后所有现有后台会话立即失效。
- 连续登录尝试受到独立限速保护。

Windows PowerShell 首次启动前指定密码：

```powershell
$env:SURVIV_ADMIN_PASSWORD = "替换为至少8位的强密码"
```

需要永久环境变量时：

```powershell
[Environment]::SetEnvironmentVariable(
    "SURVIV_ADMIN_PASSWORD",
    "替换为至少8位的强密码",
    "Machine"
)
```

环境变量只用于首次创建密码文件。密码文件已经存在时，以密码文件为准。忘记密码时，关闭服务端，删除项目根目录的 `survivio-admin-auth.json`，设置新的 `SURVIV_ADMIN_PASSWORD` 后重新启动。

## 人机自动补入设置

后台新增“人机自动补入”页面：

- **AI 统一加入间隔**：500 毫秒至 60 秒，所有模式（含 50v50）共用同一个间隔，不需要逐个播放列表设置；
- 普通模式房间补齐目标（真人 + AI）；
- **50v50 补齐人数上限（真人 + AI）**：独立于普通房间目标，可单独更改；服务端把 AI 平均分配到两个阵营；
- AI 类型占比与决策频率。

配置保存到 `survivio-config.json` 的 `botAutoFill` 字段，重启后继续生效。保存后会立即影响现有房间后续补入的 AI，无需重启服务端。降低上限不会踢出已经进入房间的 AI，只会阻止继续补入。

## 调度与负载

- 调度器每 250 毫秒检查一次，但每个房间使用独立的下次加入时间，不会因此每 250 毫秒生成 AI。
- 普通模式每次启动一个 AI。
- 50v50 继续复用批量机器人进程，进程内部按后台配置的间隔逐个连接。
- 当加入间隔较长时，加入令牌有效期会自动延长，避免批次后面的 AI 因令牌过期而无法连接。
- 真人离开导致房间人数低于目标时，自动补人可以重新启动；不再永久停留在“已补齐”状态。
