# V220 后台 UI 优化：搜打撤 AI 配装输入框 / 自动刷新保护 / 人数上限去补 0

## 需求
- 优化后台「搜打撤 AI 默认配装」编辑器的输入框布局与可读性；
- 自动刷新不要覆盖正在编辑（未保存）的输入框内容；
- 去掉「公开房间人数上限」填写数值时自动补 0 / 自动取整的行为。

## 实现

### 搜打撤 AI 配装编辑器（client/public/admin）
- 每张配装卡片增加「方案 N」序号标签，弹药、消耗品改为独立分区 + 自适应网格布局，
  不再挤在一条横向 flex 里；
- 弹药 / 消耗品输入框改用中文可读标签（9mm、7.62mm、12号霰弹、信号弹、绷带、
  医疗包、汽水、止痛药等），原英文类型名保留在 title 提示中；
- 所有数字输入框统一 `step="1" + inputmode="numeric"`（弹药原为 step=15，输入时
  不再受步进取整影响），宽度改为随网格自适应。

### 自动刷新保护（编辑状态不被打断）
- 新增 `extractionLoadoutsDirty` / `extractionLoadoutsEditing` 状态：
  编辑器内任何 input/change/focus 都会标记为「未保存」，自动刷新（以及手动刷新）
  触发 `loadExtractionAiLoadouts()` 时若存在未保存修改则跳过重绘，并给出黄色提示
  「有未保存的修改，自动刷新已暂停更新此区域」；
- 保存成功后清除 dirty 标记并重新从服务端同步；
- 房间人数上限已有草稿保护（draft 非空时不再重绘），补充「已修改未保存（自动刷新
  不会覆盖）」状态提示；
- 玩家仓库管理：当仓库输入框处于聚焦编辑状态时，自动刷新跳过该区域重绘。

### 公开房间人数上限去「补 0」
- 双排 / 四排 / 50v50 输入框的 `step` 由 2 / 4 / 2 改为 1，保存与输入监听中的
  `parseDraftNumber` 步进参数同步改为 1：输入任意整数时浏览器不再自动取整/补 0；
- 保留服务端校验（双排为 2 的倍数、四排为 4 的倍数），不合规时保存报错而不是
  静默改写输入值；表单下新增提示文案说明该行为。
