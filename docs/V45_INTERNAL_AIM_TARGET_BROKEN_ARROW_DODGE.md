# V45 内置靶场、可证明闪避、时断剑与观战输入修复

## 目标

本版本以 V44 为基础处理四项问题：

1. 将可行性闪避完整用于 LEGIT 和 HACKER，并禁止无法改变命中结果的无意义移动。
2. 重构练枪模式底层，移除外部 smartBot 标靶进程和加入凭据依赖。
3. 修复真人携带 3 个及以上空袭信标时，LEGIT/HACKER 的“时断剑”开局不触发问题。
4. 修复观战聊天输入字母 `L` 时触发全屏的问题。

## 练枪模式底层重构

### 旧架构的问题

旧练枪房由两个独立连接组成：真人客户端和外部 smartBot 移动标靶。房间创建、两个加入凭据、标靶子进程、标靶重连、玩家相机和训练装备必须按正确顺序完成。任何凭据延迟、子进程退出或首帧顺序变化，都可能形成以下半成品状态：

- 只有 `1 Alive`；
- 永久停留在 `Waiting for players...`；
- 真人武器栏为空；
- 真人客户端表现得像观众；
- 标靶进程存在但没有正确绑定当前房间。

### V45 架构

移动标靶现在由权威游戏子进程直接创建：

- 它是一个真实 `Player` 对象；
- 注册到对象表、存活玩家表和碰撞系统；
- 没有 WebSocket；
- 没有加入凭据；
- 不启动 `smartBot.ts` 或 `smartBot.js`；
- 不可能进入观战状态；
- 不受外部 AI 子进程退出影响；
- 房间创建完成时已经存在。

真人进入后立即得到所选武器、弹药和训练状态。移动标靶由服务器更新其垂直往返运动，始终禁止射击并保持无限生命。

为阻止旧客户端或旧 API 创建第二个标靶，练枪房会拒绝所有外部 `serverBot` 加入凭据。一个房间中只能存在一个内部标靶。

## LEGIT/HACKER 可证明闪避

LEGIT 与 HACKER 共用高级战斗入口，因此两者现在使用同一套严格闪避判定。

每次决策会计算：

- 每颗子弹的速度、方向、剩余射程和预计相遇时间；
- 35 ms 反应阶段；
- 反应结束后的玩家移动速度；
- 子弹与移动玩家的分段相对运动；
- 48 个候选移动方向；
- 完整移动走廊上的障碍物和地图边界；
- 原地不动时会发生的直接命中数量；
- 每个候选方向执行后仍会发生的直接命中数量。

只有候选方向能减少至少一次原本必中的直接命中时，AI 才执行闪避。

以下情况一律不闪避，并保持瞄准和射击节奏：

- 子弹本来不会命中；
- 所有合法方向仍会命中；
- 可用方向被墙体、沙袋或地图边界阻挡；
- 剩余时间不足以移出玩家碰撞圆；
- 移动不能减少直接命中数量。

这条规则不进行平衡性削弱，确认可避开的来弹会立即触发最高收益方向。

## “时断剑”空袭开局

旧实现可能在背包同步前读取到 0 个信标并永久完成初始化，之后即使实际携带 3 个以上信标也不会重新武装。

V45 改为只有权威背包明确显示至少 3 个空袭信标时才武装：

- 3 个及以上立即启动；
- 不保留后备信标；
- 当前携带的全部信标均进入开局地毯式投放计划；
- 第一枚立即开始；
- 快速持有时间为 45 ms；
- 每次释放后最快 42 ms 进入下一枚；
- 每枚重新计算敌人位置、速度和未覆盖逃生区域；
- LEGIT 使用合法可见位置或短期最后可见预测；
- HACKER 使用权威敌人状态。

实际击杀仍受地图障碍、玩家移动和游戏空袭规则影响，因此实现目标是最大化覆盖和连续投放，而不是在验证报告中虚构必杀结果。

## 观战聊天输入修复

全屏键绑定在窗口级 `keyup` 上。旧观战聊天框只阻止了 `keydown`，因此输入 `L` 后的 `keyup` 仍会冒泡并触发全屏。

V45 同时处理：

- `keydown`；
- `keyup`；
- `keypress`；
- 原生 `input`、`textarea` 和 `contenteditable` 焦点保护；
- 全局游戏输入系统的编辑控件过滤。

在观战消息框中输入 `L` 不会再切换全屏，也不会触发游戏按键。
