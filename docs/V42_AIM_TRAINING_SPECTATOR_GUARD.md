# V42 练枪模式观战状态隔离与标靶恢复

## 问题表现

练枪房可能出现以下组合状态：

- 画面类似观战或未激活角色；
- `Alive` 只显示 1；
- 武器栏、弹药和玩家状态为空；
- 顶部长期显示 `Waiting for players...`；
- 移动标靶不可见，刷新后仍可能复现。

该现象不是单一 UI 文本错误，而是练枪连接身份、相机目标和标靶生命周期之间的竞态。

## 根因

### 1. 客户端通过相机目标推断连接身份

旧客户端使用 `activePlayerId !== localPlayerId` 推断自己是否处于观战。移动标靶断线、重连或首帧到达顺序变化时，相机目标可能暂时指向标靶，真人连接因此进入伪观战状态。

### 2. 服务端没有持续监督移动标靶

练枪 API 只在创建房间时等待一次标靶连接。标靶在 API 返回后退出时，房间不会持续补回标靶。

### 3. 标靶缺失时不发送训练状态

旧服务端只在 `serverBotCount > 0` 时发送训练统计。标靶掉线后，客户端收不到新的状态包，也就无法把等待覆盖层改为“重连中”或在标靶恢复后关闭它。

### 4. 练枪模式仍会接收竞技场回合 UI

通用 `ArenaRound` 消息可以覆盖练枪界面，使训练房更接近错误的观战/等待状态。

## 修复内容

### 显式连接角色

`JoinedMsg` 新增两项服务端权威字段：

- `spectatorOnly`：该凭据是否为专用观众；
- `trainingTarget`：该连接是否为移动标靶。

客户端不再通过镜头目标推断连接身份。

网络协议版本从 80 提升到 81。旧网页端会被明确拒绝，不能再与 V42 服务端按错位消息格式连接。

### 真人相机强制绑定自身

服务端对 `aim_training` 中的真人连接执行以下约束：

- 清除遗留的 `spectating` 目标；
- 关闭自由观战相机；
- 活动玩家始终为真人自身；
- 标靶断线或重连不改变真人连接角色。

客户端也有对应保护：练枪真人始终使用自己的 `localPlayerId`，并忽略非观众连接收到的观战覆盖数据。

### 持续标靶监督

`GameServer` 为每个私人练枪房保存独立状态，并在房间生命周期循环中检查：

- 移动标靶是否仍在线；
- 是否已有一个待连接的标靶进程；
- 房间是否仍有真人或有效的真人加入预留。

标靶异常退出后，服务端会签发全新的服务器机器人凭据并自动重启。不存在真人或加入预留时，房间仍可正常回收，不会留下永久空房。

### 可恢复的训练状态

`AimTrainingStatsMsg` 新增 `targetReady`：

- `true`：显示“标靶在线”，关闭等待覆盖层；
- `false`：显示“移动标靶正在自动重连…”，保留真人角色、武器和训练界面。

训练统计现在即使标靶暂时缺失也会发送给真人。

### UI 隔离

- 练枪模式忽略 `ArenaRound` 界面；
- 非观众练枪连接忽略 `SpectatorOverlay`；
- 进入练枪房时清除上一次观战留下的自由相机和观战 UI；
- 从练枪大厅加入时显式清除 `sharedSpectator`。

## 正式多进程验证

验证环境使用 `NODE_ENV=production` 和默认 `processMode=multi`：

1. 创建 AK-47、80 距离、无限弹匣练枪房；
2. API 返回 `ready=true`；
3. 移动标靶进程 PID 3568 成功加入；
4. 真人探针进入，活动玩家 id 为 13，装备包含 AK-47；
5. 强制结束 PID 3568；
6. 服务端记录 `Aim-training target respawn requested`；
7. 新标靶进程 PID 3629 加入同一房间；
8. 真人连接未退出，活动玩家仍为 13，AK-47 仍在武器栏。

这验证了截图所示的伪观战状态和标靶掉线恢复路径，而不只是单元测试中的理想创建顺序。

## 启动与缓存

使用：

```text
START_V42.cmd
```

启动器拒绝复用已占用的 3000/8001 端口，并清理 Vite 缓存。静态部署需要重新运行 `build-complete.ps1`，构建脚本会检查 `V42_AIM_TRAINING_SPECTATOR_GUARD` 标记。
